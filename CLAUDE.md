# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

This is a **fresh Unity project** (`PVGas`), created from the default 3D URP template. There is no gameplay code yet — `Assets/` contains only the stock template: `SampleScene.unity`, URP render pipeline assets under `Assets/Settings/`, the default `InputSystem_Actions.inputactions`, and the `TutorialInfo` readme scripts (`Assets/TutorialInfo/Scripts/Readme.cs`, `ReadmeEditor.cs` — safe to delete once no longer needed, they just render the welcome panel in the Editor).

Not a git repository yet. If version control is needed, `git init` first (and add a Unity `.gitignore` covering `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`, `*.csproj`, `*.sln`/`*.slnx` — these are regenerated by the Editor and currently present in the working tree).

## Environment

- Unity Editor version: **6000.0.64f1** (Unity 6) — must match exactly for the Library cache to stay valid.
- Render pipeline: **Universal Render Pipeline (URP) 17.0.4**, with separate PC (`PC_RPAsset`/`PC_Renderer`) and Mobile (`Mobile_RPAsset`/`Mobile_Renderer`) pipeline assets under `Assets/Settings/`.
- Input: new **Input System** package (1.17.0) via `Assets/InputSystem_Actions.inputactions`, not the legacy Input Manager.
- Other notable packages: AI Navigation, Timeline, Visual Scripting, Multiplayer Center, Unity AI Assistant/Inference. See `Packages/manifest.json` for the full list.

## Working with this codebase

- C# scripts belong under `Assets/` (by convention, split `Scripts/` from `Scripts/Editor/` for editor-only code, matching the existing `TutorialInfo/Scripts/Editor` pattern) — editor-only scripts must live in a folder named `Editor` so Unity excludes them from player builds.
- Scenes live in `Assets/Scenes/`; project-wide rendering/quality config lives in `Assets/Settings/` and `ProjectSettings/`.
- There is no custom build/test/lint tooling configured yet (no CI scripts, no EditMode/PlayMode test assemblies beyond the stock `com.unity.test-framework` package). Builds, play-testing, and running the Test Runner are done from the Unity Editor (or `Unity.exe -batchmode` / Unity CLI) rather than via any repo-specific script.
- `Assembly-CSharp.csproj`, `Assembly-CSharp-Editor.csproj`, and `PVGas.slnx` are IDE project files auto-generated by Unity's VS/Rider package integration — don't hand-edit them; regenerate via the Editor if they drift.
